How a ticket moves through SupportFlow

  1. Precheck the ticket

    Short, non-English or non-Latin text goes to manual review. The model never sees it.

  2. Classify the ticket

    The model returns six fields. A reply that fails the schema is retried once.

  3. Flag the ticket

    Code adds flags for low confidence, an angry P1, or legal and refund words.

  4. Hand the ticket over

    It waits as Needs review; every accept or override joins the audit trail.

The ticket pipeline runs on a free LLM

The classifier is a LangGraph graph behind FastAPI. Tickets, analyses and the audit trail live in PostgreSQL; the model is openai/gpt-oss-120b on Groq's free tier.

What works in SupportFlow today?

Classification, the safety rules, the intake form and the audit trail run on the backend. Drafting and escalation still use mock data.

Does SupportFlow ever email a customer?

No. Drafts wait for an agent to edit and approve them, and Slack stays simulated until credentials are added.

Which ticket languages are supported?

English only. Other languages and non-Latin scripts go to manual review before the model sees them.

Where does ticket text go?

Into your PostgreSQL, and to the model provider for classification. It is never written to the server logs.
